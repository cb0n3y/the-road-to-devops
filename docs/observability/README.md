# Observability

## Introduction

Observability is the capability of understanding the internal state of systems by analyzing the telemetry they produce. While traditional monitoring focuses on detecting failures and triggering alerts, observability provides the tools and data required to understand **why** an issue occurred and how it impacts the overall system.

Modern observability relies on collecting and correlating different telemetry signals, enabling engineers to troubleshoot distributed applications and infrastructure efficiently.

---

## The Three Pillars of Observability

### Metrics

Metrics are numerical measurements collected over time that describe the health and performance of systems.

Examples include:

* CPU utilization
* Memory usage
* Network throughput
* Request latency
* Error rates

Metrics are commonly used for dashboards, alerting, and capacity planning.

---

### Logs

Logs are timestamped records describing events generated by applications, operating systems, or infrastructure components.

Logs are useful for:

* Troubleshooting failures
* Auditing activity
* Security investigations
* Debugging applications

---

### Traces

Distributed traces follow a request as it travels across multiple services.

Tracing helps identify:

* Performance bottlenecks
* Service dependencies
* High latency operations
* Root causes of failures

Tracing has become essential in microservice and cloud-native environments.
